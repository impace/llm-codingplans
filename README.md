# LLM CodePlans Pro

油猴脚本：对比大模型代码订阅、检查官方定价/更新页面，并按“单账号极限基准 + 自选购物车”估算大用量场景的月成本。

## 安装

1. 安装 Tampermonkey。
2. 打开 `LLMCodePlansPro.user.js`，复制到 Tampermonkey 的新脚本中并保存。
3. 打开任意网页，右下角会出现悬浮球。点击悬浮球打开面板。

脚本匹配所有网页，是为了让后台动态页面采集标签页也能运行；它只在用户点击检查或打开面板后执行对应逻辑。

## 四个页面

- **套餐比价矩阵**：查看厂商、套餐、额度规则、主力模型、优惠和避坑提示。
- **动态更新雷达**：采集官方定价和更新链接，保存正文指纹并比较变化。
- **月用量成本测算**：先看每个账号的单账号极限，再手动勾选账号和数量汇总。
- **厂商配置**：启用/移除厂商，修改定价和更新地址，配置 AI 与汇率。

## 动态更新雷达按钮

- **① 全量抓取检查**：串行抓取所有已启用厂商的定价和更新地址，会打开后台采集标签页，速度较慢，只抓取，不自动调用 AI。
- **② 仅抓取定价**：只抓取定价/套餐地址，适合先核对成本，只抓取，不自动调用 AI。
- **③ 刷新本地状态**：不联网，只重新显示已经保存的结果。

每条来源还有两个动作：

- **抓取检查**：抓取 HTTP 正文或使用浏览器渲染后抓取正文，并比较历史指纹；如果开启“首次检查、正文变化或正文过短时自动调用 AI”，满足条件时会产生 AI 请求。
- **AI重新抓取复核**：强制重新采集正文并尝试调用已配置的 OpenAI Chat Completions 兼容接口，抽取价格、额度和模型；不需要先点击“抓取检查”。

AI 复核不是每条来源都必须点击。每条来源下方会显示状态：黄色“建议点击”表示页面发生变化、正文不完整或确定性抽取没有识别到有效信号，建议点击但不是强制；灰色“可选”表示当前正文没有变化，想进一步确认时再点；绿色“已完成”表示本次已经有 AI 结果；红色“未完成/暂不可执行”表示需要先解决抓取失败或 AI 配置问题。按钮变成“建议 AI复核”时，就是当前最值得点的来源。

“页面可访问；动态渲染，未比较历史正文”表示页面本身打开了，但这是第一次成功采集，尚无历史指纹可比较；不等于厂商数据已经被正确抽取。正文、确定性抽取、AI 摘要和失败原因会显示在该来源卡片下方。

## AI 抽取

AI 默认关闭。到“厂商配置”中填写：

- Endpoint，例如 `https://api.openai.com/v1/chat/completions`
- 模型名，例如 `gpt-4o-mini`
- API Key
- 普通抓取遇到首次抓取、正文变化或正文过短时是否自动调用

AI 结果会标记为“待人工确认”，不会自动覆盖 `PROVIDERS_DATA` 或购物车基准。脚本会保留原始币种、证据短句、正文指纹和汇率快照。模型被要求不能根据访问者 IP 猜币种；如果页面没有明确币种，会保留为 `UNKNOWN`。

AI 不需要每次都调用：顶部两个批量按钮永远只抓取，不调用 AI；单条“抓取检查”默认也不调用，只有勾选“普通抓取遇到首次抓取、正文变化或正文过短时自动调用 AI”后，满足条件才会调用。需要立即复核某个来源时，直接点击“AI重新抓取复核”，它会强制重新抓正文并尝试调用 AI，不需要先点“抓取检查”。若 AI 未启用、Key/Endpoint 不完整、正文少于 120 字，或页面被登录墙/验证码拦截，结果会显示未执行或失败原因；这些情况无法靠 AI 绕过。

确认 AI 结果后，如需更新测算基准，应修改脚本中的 `CART_ACCOUNT_ROWS`，而不是在购物车里临时填覆盖值。这样每次测算都使用清晰、可复核的基准。

API Key 只保存于 Tampermonkey 本地存储，不写入脚本文件。使用第三方 Endpoint 前请确认其隐私、费用和数据保留政策。

## 配置与数据保存位置

脚本通过 Tampermonkey 的 `GM_setValue/GM_getValue` 保存用户配置，位置是当前浏览器用户配置下的油猴脚本本地存储，不是项目目录、脚本文件、网页 `localStorage` 或 Git。具体磁盘路径由浏览器、Tampermonkey 版本和用户配置决定，不建议直接编辑其内部文件。

主要键如下：

- `llm_app_settings_v1`：AI 开关、Endpoint、模型、API Key、自动触发选项和汇率。
- `llm_provider_settings_v2`：厂商启用开关、定价/更新地址覆盖。
- `llm_calc_cart_v1`：目标用量、API 兜底基准和购物车勾选/购买数量。
- `llm_source_probe_v2_*`：抓取正文、历史指纹和失败状态。
- `llm_ai_snapshot_v1_*`：最近一次 AI 复核/失败状态及结构化结果。
- `llm_view_*`、`llm_floater_pos`：来源已读状态和悬浮球位置。

脚本内置基准仍保存在 `LLMCodePlansPro.user.js` 的 `PROVIDERS_DATA` 和 `CART_ACCOUNT_ROWS` 中；厂商配置页保存的是本地覆盖项。API Key 虽不会进入仓库，但 Tampermonkey 存储不是独立密码保险箱；清理扩展数据、卸载脚本或更换浏览器后可能丢失。设置页的“恢复初始默认”会清除 AI/厂商/汇率/购物车配置，但不会自动删除历史抓取缓存。

## 币种

在“厂商配置”中维护：

```text
USD=7.20
EUR=8.00
JPY=0.050
HKD=0.92
```

含义是“1 外币 = 多少人民币”。页面展示会同时保留原始金额和人民币折算值。IP 导致页面显示 USD、HKD 或其他地区价格时，应以页面明确标注的币种为准，并在“厂商配置”中修正汇率；不要把地区变化通过购物车临时覆盖掩盖掉。

## 测算口径

测算器默认目标是 `20 B Token`，但可以改成任意值。

1. 每个账号显示一个单账号月度容量：官方明确给出的数值、官方 Credits 数值，或“未知”。
2. 用户只需勾选账号并填写购买数量；系统只做“数量 × 单账号容量”的汇总。
3. 未知容量保持未知，不纳入已知容量和达成率，也不会要求用户手动补填或被脚本擅自换算成 Token。
4. 未知价格保持待定，不会静默按 0 计入；要修正时更新脚本中的 `CART_ACCOUNT_ROWS` 基准。
5. 已知容量不足的部分，按用户选择的 API 兜底单价估算；这只是缺口的参考成本，不代表订阅一定允许 API 调用。
6. 结果同时给出订阅费、已知容量、达成率、API 缺口成本、购物车有效成本、纯 API 基准和相对节省。

MiMo 等页面的“Credits”不必然等于裸 Token，脚本会在结果中提示；调用次数、积分和消息数也不会被脚本擅自换算成 Token。对于未公开稳定 Token 容量的订阅，结果只展示已知容量下界，不把未知部分伪装成可比较的 Token 数。

## 数据可靠性边界

静态页面使用 HTTP 正文；识别为 JS 壳、正文过短或已知动态页面时，会尝试打开后台浏览器标签页等待渲染。登录墙、地区限制、验证码、403、页面只对特定账号展示的价格，仍可能无法取得；此时雷达会保留失败原因或要求人工复核。AI 可以整理已经取得的正文，不能绕过登录、403 或验证码。

如果某个来源曾经保存过空正文，服务器后续返回 `304 Not Modified` 时，脚本会自动绕过空缓存重新请求；如果 HTTP 返回成功但响应体为空，也会明确标记为“响应正文为空”，并尝试动态渲染，不再显示成正常的“静态正文 · 0 字”。
